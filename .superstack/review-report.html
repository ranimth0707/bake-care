Arisan protocol review

Outcome: B. The repeated-winner correctness bug is fixed and the fund-transfer paths retain signer, PDA, ownership, and checked-arithmetic protections.

Resolved high-severity correctness issue

The old draw used seed % member_count, so a prior winner could be selected again. A compact on-chain winner bitmap now removes prior recipients from the candidate population before selection. Claim updates the bitmap atomically.

Security checks

  • Creator has no instruction that transfers the pot to an arbitrary destination.
  • Pot and bond PDAs are re-derived from the circle and signed only by program seeds.
  • Only the selected, signing wallet can claim, and its Member account is PDA-, wallet-, seat-, payment-, activity-, and winner-checked.
  • Legacy roster migration verifies Anchor ownership/discriminators, circle identity, seat bounds, complete coverage, and winner counts.
  • Value arithmetic uses checked operations on the draw/claim path.

Open risks

  • Economic default: a wallet cannot be forced to make future payments. Once optional collateral is exhausted, later pots can be short.
  • Upgrade trust: the program remains upgradeable by a single authority. Move it to a multisig before material TVL; freeze only after a mature audit.
  • Dependencies: npm reports transitively inherited advisories in Anchor/Web3 dependencies with no upstream fix available.

Verification

3 Rust bitmap tests, 49 frontend/relayer tests, TypeScript production build, live program upgrade verification, and a 30,591-CU simulation against the existing “Masak Masak” state.
